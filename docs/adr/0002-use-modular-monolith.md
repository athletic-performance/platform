# ADR 0002 — Использовать modular monolith для API

## Context

Продуктовая модель ещё уточняется. Выделение микросервисов на старте увеличит
операционную сложность без подтверждённой необходимости.

## Decision

Реализовать backend как NestJS modular monolith с REST API.
Границы будущих доменов отражаются модулями внутри одного деплой-юнита.

## Consequences

- Плюсы: проще локальный запуск, транзакции в одной БД, быстрее итерации MVP.
- Минусы: нужна дисциплина модульных границ, чтобы не получить «большой ком».
- Вынос в отдельные сервисы возможен позже по доказанной нагрузке/ownership.
